# 建模模块开发规则

本文件适用于 `modeling/` 及其子目录。开发前阅读本文件和 `README.md`。用户后续明确指定的需求优先；不要把本轮授权扩展成其他模块的改造。

## 定位与本期边界

- **数字化建模 = 参数化节点建模**，入口是 `parametric/index.html`。现阶段支持直线、圆形、矩形，拾取节点，节点连线，直线路径放样，局部三维预览及参数修改。
- **三维建模**是主程序中的独立预留页 `threeDModelingSection`。参数化模块内的三维预览不等于该功能已上线；在用户确认方案前不添加三维建模引擎、云服务或新的依赖。
- 模型是局部几何试验，坐标单位尚未标定。当前放样输出为带端盖的实体三角网格，**不是具有壁厚的真实中空灌溉管**。不要把它当成水力校核、工程量、材料清单或可施工成果。
- 模型目前只存于 iframe 内存。切换顶部导航须保留状态；刷新／关闭会清空，界面必须持续如实提示。未实现的保存、STL/OBJ 导出等，不得展示为已可用功能。

## 修改范围

- 常规完善只修改 `parametric/` 与相关测试／文档。不要重写宿主 `index.html`，不要改宿主 CSS、导航系统、水力公式、分区规则、地图测量、二级／三级管线、报价或材料清单。
- `workspace.css`、`integration.js` 只负责容器、加载和主题适配，不得加入几何算法或业务数据转换。只有明确的接入需求才修改这两处及宿主入口。
- WorkBuddy 中的小样是来源参考，部署副本以当前仓库 `modeling/parametric/` 为准。不要双向覆盖或再次整体复制旧小样，避免丢失集成适配。
- `parametric/embedded.html` 是生成产物，不手工修改。修改模块源文件后执行 `node modeling/build.cjs` 并一起交付生成页；`--check` 可检测过期。它为本地 file:// 的 sandbox 提供无外部文件加载的版本，避免为兼容本地运行放松隔离。
- 做小范围修改，不全局格式化、不顺手删除其他 agent 的改动。变更前检查 Git 状态，保留无关修改。

## 隔离与接口

- 保留宿主 iframe 的 `sandbox="allow-scripts"`。不添加 `allow-same-origin`，不通过 `parent.document`、`top`、共享全局变量、宿主 storage 等方式接入灌溉数据。
- v1 只允许两个消息：子页 `ready` 与宿主 `theme`。规范见 README。消息接收方必须验证 `event.source`、`channel`、`version`、`type`；颜色还须通过白名单及六位 hex 校验。
- 不增加通用执行代码、任意 URL 导航、远程脚本加载或任意父页面读写消息。CSP 禁止连接外部服务；不得为“方便开发”移除隔离。
- **本期没有灌溉业务数据接口**。将来需要导入管线、保存模型、写入材料清单时，先根据用户需求制定独立、版本化的数据契约，包含单位、坐标系、ID、校验、容量限制、错误语义、用户触发及回滚，再实现。不要静默回写主系统。

## 内部结构与几何规则

- `vec3.js`：向量运算；`geometry.js`：纯几何；`viewport2d.js`：绘制／拾取；`nodeeditor.js`：节点及连线；`renderer3d.js`：显示；`app.js`：状态和求值；`splitters.js`：三个大区之间的可拖动分隔条。不要把 DOM 操作混入纯几何计算。
- **新增脚本必须遵循既有 IIFE 约定**：文件形如 `(function (global) { 'use strict'; … })(typeof window !== 'undefined' ? window : globalThis);`。注意项目里的 `global` 是**形参**、不是全局变量，漏写这一层会立刻 `ReferenceError` 并中断整段脚本。同时要在 `index.html` 按依赖顺序引入，并把 `modeling/build.cjs` 里的脚本数量约束（当前为 8）同步加一，否则打包会主动报错。
- 新节点先扩展 `NodeEditor.TEMPLATES`，再扩展 `app.js` 的求值分支。保留稳定的模板 key、端口 key 和类型；不凭显示名称关联节点。
- 保留缺失输入、自连、图环路、零长度路径的处理。新增几何能力须校验有限数、合法维度及端口类型；避免 NaN、无限递归和退化网格。既有问题须先复现，不凭注释宣称已经支持。
- 原型仍有待完善事项：未对全部非有限数／零截面／不支持的截面类型作严格拒绝；快速示例会追加图形；节点区及画布主要为鼠标交互。修复须限于模块并补测试，不得误报为宿主集成保证。
- **电池画布坐标约定（改动前必读）**：节点挂在内层 `#nodeCanvas`，由它的 `transform: translate(pan) scale(s)` 实现缩放／平移；`svg#wires` 留在外层 `#nodeEditor`、**不参与 transform**。这样 `_portCenter()` 用 `getBoundingClientRect()` 量出的容器坐标天然等同 SVG 坐标系，缩放后只需 `_drawWires()` 重绘。若把 SVG 也放进缩放层，或改用百分比／视口单位定位节点，连线端点会偏离端口——必须先跑 `tests/node_viewport.cjs` 的 A5 确认偏差 < 2.5px。
- 节点拖拽要把屏幕位移除以 `this.scale` 换算回画布世界坐标；端口连线命中半径应与 `scale` 联动，否则小倍率下难以点中。
- 折叠只隐藏 `.pick-box` 与 `.node-status`，**端口必须保持可见**（连线依赖端口测量位置）。新增内容若需折叠时也隐藏，先确认它没有承载连线端点。

## 界面

- 延续宿主的深绿导航、浅色面板、绿色主要操作、蓝色输入／水力色、红色异常提示。优先复用 `--u-*` 变量；不要另造营销页、巨幅标题、大圆角或厚阴影。
- 输入端蓝、输出端绿；警告和失败保留可区分状态。主题同步只改颜色，不能用消息注入任意 CSS。
- 窄屏允许上下排列和节点区域横向滚动。已有鼠标拖动模型不等于完整触摸支持，不承诺未验证的移动端能力。
- 保持相对资源路径、运行时无构建步骤、离线可用、独立页面可打开。源码修改后只需现有的零依赖打包命令，不要随意引入框架或 CDN。
- **主区固定为 12 个编号区域**，用户按编号提需求：① 主导航 ② 页面标题栏 ③ 流程面包屑 ④ 绘图工具栏 ⑤ 2D 绘图区 ⑥ 绘制提示条 ⑦ 三维预览区 ⑧ 参数调节面板（①–⑧ 归属左栏上下文）⑨ 电池工具栏 ⑩ 节点编辑画布 ⑪ 操作说明条 ⑫ 状态栏。当前 ④ 与 ⑨ 已从各自的区里抽出来，成为整页最左／最右的两条**页面级竖栏**，编号不变。改动前先核对编号对应的元素，编好号不要重排。
- **⑦ 三维预览与 ⑧ 参数调节必须左右并排**（二者同在 `#bottomRow` 内），不再上下堆叠；`#previewWrap` 横向伸缩，`.props` 定宽 320px 且不超过 46%，窄于 760px 时回退为上下堆叠。
- **三个大区由可拖动分隔条分隔**：A 绘图区（⑤⑥ `#vp2dWrap`）｜B 参数+三维区（⑦⑧，即 `#bottomRow`）｜C 电池区（⑩⑪ `#right`）。`#splitH` 在 A 与 B 之间、只做上下拖动；`#splitV` 在 B/C 与 C 之间，宽屏左右拖动、堆叠模式自动转成上下拖动。实现见 `js/splitters.js`，**未拖动过时不写任何内联样式**，默认观感与静态布局逐像素一致；双击分隔条复位。
- **分隔条不得变成「多余留白」**：`#main` 无 gap、`#left` 无 `border-right`，两区之间的间隙必须**恰好等于分隔条宽度**且被分隔条完全占据。旧契约「间距为 0、无分隔线」已被三区化取代，不能再用——判断时必须同时满足「间隙 == 条宽 + 条完整占满 + 无边框 + 无 gap」，任何一条单独判都可能恒真。
- **④ 绘图工具栏与 ⑨ 电池工具栏是页面级竖栏**：分别放在 `#drawRail`（整页最左）与 `#battRail`（整页最右），内部为 `flex-direction:column`，按钮上下堆叠、宽度受侧栏约束。二者**不参与三大区的尺寸分配**：`#leftToolbar` / `#nodeToolbar` 的 DOM 归属已改变，但 id 与按钮结构保持不变（`app.js` 用 `#leftToolbar .tool[data-mode]` 选择器、`nodeZoomLabel` 用 id 取，移动位置不影响逻辑）。矮屏堆叠模式下两条竖栏自动变回整幅横条，不再占用横向空间。
- **`splitV` 的可用空间必须剔除两侧竖栏**：`#main` 现在同时容纳两条 rail 与三个区，`#splitV` 计算极限时**不能再用 `#main` 的总尺寸**，否则电池区会被压穿 260px 保底（实测右极限只剩 60px）。正确做法是用「左栏 + 分隔条 + 电池区」的实测宽度之和。凡是往 `#main` 里再加固定宽度子元素（侧栏、托盘），都要回到 `splitters.js` 复核这一处。
- **拖动改变尺寸后必须触发重绘**：`app.js` 已监听 `window` 的 resize 并统一调用 `viewport.resize()`／`renderer.resize()`／`nodeEditor.render()`，因此分隔条只需派发一次 resize 事件即可让三个区一起重排。断言时要比对 canvas 的**位图尺寸**（`width`/`height` 属性）而不只是容器尺寸，否则「布局变了但画面被拉伸」会被漏掉。

## 验收与交付

- `node --test modeling/tests/geometry.test.cjs`：纯几何回归。
- `node modeling/build.cjs --check`：确认生成的离线嵌入页与源码一致。
- `node modeling/tests/smoke.cjs`：浏览器集成验证，依赖本机 Playwright 与 Edge，环境配置见 README。新版 Edge 已移除 old headless，启动参数必须带 `args` 里的 `--headless=new`，否则报 “Old Headless mode has been removed”，表现为 launch 直接失败（其余专项脚本已带该参数）。
- `node modeling/tests/node_viewport.cjs [root]`：电池区专项回归，覆盖画布缩放／平移、节点宽度、折叠／展开、悬停说明。改 `nodeeditor.js` 的坐标、折叠或标题区后必须跑；传改动前副本目录做反向验证（改动前应为 2/13）。
- `node modeling/tests/layout_regions.cjs [root]`：布局分区专项回归，覆盖 ⑦⑧ 左右并排、左右栏贴合、2D 区未被压扁，在 1600/1440/1200 三档视口各验一遍。改 `#main`／`#left`／`#bottomRow`／`.preview`／`.props` 的布局后必须跑；传改动前副本目录做反向验证（三区化之后，改动前应为 13/16——B1 三档会如实报红，因为旧版没有分隔条）。
- `node modeling/tests/layout_splitters.cjs [root]`：三区分隔条专项回归，覆盖两条分隔条的位置与细线宽度、拖动确实改变三区尺寸、最小尺寸保底、双击复位、拖动后三个画布位图同步重绘、矮屏堆叠模式下方向自适应。改 `splitters.js`／`#splitH`／`#splitV`／`#left`／`#bottomRow` 的尺寸逻辑后必须跑；传改动前副本目录做反向验证（改动前应为 2/20）。
- `node modeling/tests/layout_rails.cjs [root]`：竖向工具栏专项回归，覆盖两条侧栏是否紧贴整页左右缘、是否在对应区的外侧、按钮是否竖向堆叠（上下排列 + 中心对齐 + 不折行）、侧栏是否纵向铺满主体、`#leftToolbar` / `#nodeToolbar` 的 DOM 归属、矮屏堆叠模式下是否转为横条。改 `#drawRail`／`#battRail`／`.rail*` 样式或移动这两个工具栏时必须跑；传改动前副本目录做反向验证（改动前应为 1/12——只有「无 JS 报错」该过）。
- 断言悬停提示等「伪元素内容」时，**必须校验 `::after` 的 `content` 真的渲染出文案**：缺规则时 `content` 为 `none`，而 `opacity`／`visibility` 仍是默认值，只判可见性会得到永远通过的假绿。
- 断言尺寸类改动时，**「尺寸合法」「两者相等」这类判据在功能缺失时天然成立**，是恒真假绿。必须补上「尺寸确实因操作而改变」的硬条件（例如两次相反方向的极限操作之间必须有明显差值）。`layout_splitters.cjs` 的 B4／C2／C3／D2 最初就是这样漏的，靠反向验证才抓出来。
- 本地双击和 HTTP 模式都要检查：入口可达、示例出模型、拾取／参数修改／连线／删除正常、切换保留状态、返回灌溉计算正常、无新增脚本异常。
- 检查桌面与窄屏、空输入状态、加载失败提示、主题同步、非法消息被忽略、主系统数据隔离；涉及保存后另测刷新与恢复。
- 交付说明写清：实际改动、验证结果、仍未支持的事项。不得把“保留扩展点”写成“功能已实现”。

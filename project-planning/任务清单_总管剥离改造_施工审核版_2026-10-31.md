# 总管剥离改造：审核后施工清单

> 版本：审核稿 v1｜日期：2026-10-31
> 目标：在线地图页由用户绘制总管；分区与管路工作区停止生成总管几何，读取同一地块的总管数据供显示、统计和水力使用。
> 状态：可开始只读勘察；涉及产品口径的实现必须等本文“待决策”拍板。本文不授权发布、推送或部署。

## 1. 给施工 Agent 的开工要求

1. 先读本文件、仓库 `AGENTS.md`、[总管剥离依赖清单](总管剥离改造_依赖清单_2026-10-31.md)；依赖清单中的行号和“无需修改”判断仅作搜索线索，必须对照当前 HEAD 与工作树重核。
2. 查看 `git status --short` 和相关文件 diff，保留其他 Agent 的未提交改动；不得 reset、checkout 覆盖或批量暂存。
3. 先交付只读勘察结果：调用链、数据归属、坐标系、模型/适配器写路径、所有消费者、测试现状、风险和待决策。未经产品决策，不开始 T2、T3、T4 或 T6。
4. 任何代码修改仅限经用户/主 Agent 明确分配的任务卡；每卡独立 diff、可回滚、提供运行证据。不要自行发布、push 或部署。
5. `frontPipe` 同名不同义：`tlDiagramData.frontPipe` 是几何；水力结果中的 `r.frontPipe`（例如管径、内径、流速）是计算结果。剥离前者时不得删除、重命名或改坏后者。
6. 沿用单一 CAD 画布：地图总管叠加到同一地块/视口；切工具或图层不能另开视图或造成比例变化。角度匹配沿用“生成施工图”既有行为，不列入本改造。

## 2. 已核实边界与尚待证实内容

### 可作为调查起点的事实

- 三级图生成入口在 `mod/inline-09.js`，目前存在 `frontPipe` 生成/兜底路径；入口还把 `frontPipe` 作为几何完整性条件，直接置空可能导致整图返回空结果。
- `frontPipe` 几何还参与主管接入定位、节点生成、绘制/导出、材料长度、配件统计和水力长度来源；这些消费点要逐一判定是否转为地图数据、长度兜底、或无总管空状态。
- L2 规范模型使用 `network` 存内部管网，模型和适配器有白名单投影；新字段不能只塞进运行时对象。当前 L2 单地块更新会重写被更新字段，CAS 比较哪些字段需从当前实现精确核对。
- 在线地图、分区页及多地块组各有地块身份与快照/交接路径。总管数据必须绑定稳定地块身份与明确坐标框架，不能仅依赖共享全局键或当前页内存。

### 必须重新核对，禁止照抄旧行号

- 自动总管生成的全部入口、空值访问点和整图 early-return 条件。
- `plot.network`、`plot.revision`、项目快照和组适配器的真实替换、CAS、投影语义。
- 总管几何的坐标来源、旋转/镜像变换、水源连接段、分区总流量及现有测试门禁。
- 依赖清单中每个消费者当前是否仍有效，以及 `verify_ry_tool.js`、测试文件是否已跟踪且命令在本机可运行。

不得把“某处使用 JSON.stringify”“更新函数当前未赋值某字段”直接推导为兼容、无冲突或无需迁移。

## 4. 分阶段计划与门槛

### P0 只读勘察（可立即开始）

- 盘点完整数据流：地图输入 → 地块库/桥 → canonical → 页面运行态 → 生成/水力/材料/DXF。
- 对所有 `frontPipe` 命中逐项归类：几何或水力结果；生产代码或历史/测试；读或写；地块身份；是否在无总管时可运行。
- 追踪单地块与组地块适配器、恢复、撤销、revision/CAS、跨页回传和 PWA 缓存版本。
- 产出消费者表、可复现测试清单、D1-D8 决策记录、推荐模型方案和拆分后的真实估时。
- 验收：所有结论附当前文件/符号与证据；明确哪些只是推断；不改业务源码。

### P1 空值安全（仅在确认不会改变正常图面后实施）

- 为“无总管”的三级几何生成、取景、节点、分段、材料、水力与导出路径建立明确空状态。
- 不可用全局 `if (!frontPipe) return` 把整图短路；分区内部主管/支管/滴灌带必须仍可生成。
- 验收：同一已保存夹具在改前/改后比较非总管几何；无总管时不抛错且内部管网仍绘制；空总管输出的 UI 与水力状态明确。

### P2 规范数据模型与跨页权威（D1/D2/D5/D8 决定后）

- 先定权威数据对象和坐标框架，再实现校验、导入/导出、单地块与组地块投影、快照、revision/CAS、旧档兼容。
- 明确在线地图编辑与分区页只读显示之间的冲突策略，避免 A/B 同时编辑互相静默覆盖；提供事务失败提示与恢复。
- 验收：A 画/编辑/保存/刷新；B 读取同一地块总管且只读；切换地块不串图；组地块按决策正确隔离/共享；连续 L2 编辑不丢总管；旧快照打开/保存/回滚可复现。

### P3 消费端改造（P1/P2 完成后）

- 按当前依赖表逐一改渲染、取景、节点、分段测量、材料、统计、水力、图纸、DXF 和快照。
- 保留历史字段读取契约，除非兼容方案已批准；水力结果 `r.frontPipe` 不得误改。
- 验收：有总管/无总管各跑一遍；每个消费者检查结果与选定口径一致，材料无重复计量，水力不把未完成工程伪装成通过。

### P4 下线 B 页总管交互（P3 后）

- 移除或禁用自动总管专属拖点、水源端点依赖和长度控件；确认 `window` 暴露接口及插件/外部调用。
- 验收：B 页无死控件/无误导提示，分区和内部管网仍正常；多地块逐块/整组模式均符合权限与数据边界。

### P5 地图手绘交互（独立规格评审后）

- 先出交互规格与原型：绘制/结束/取消/捕捉/选择/拖点/属性/屏蔽/撤销/键盘/触屏/无障碍。
- 坐标捕捉按屏幕像素定义；确定底图投影与画布米制之间的可逆转换；区分绘图距离与水力有效长度。
- 验收：真实浏览器和目标视口；地图缩放/平移后总管与地块正确重合；可连续保存/恢复；总管专属操作不能改写回传只读管网层。

### P6 总回归与交付

- 跑仓库当前有效的静态、Node、模型、浏览器、发布引用与必要视觉回归；先查 package scripts/CI，不能照搬清单中的历史期望数。
- 对同一代表性工程验证地图、分区、组地块、三级图、材料、水力、导出、刷新恢复与地块切换。
- 核对资源引用、Service Worker CORE/VERSION、HTML/CSS 查询版本是否按仓库当前策略同步。
- 提供改动文件、测试命令与结果、剩余风险、回滚点；未经用户明确授权不提交、不推送、不部署。

## 5. 实施纪律与禁止事项

- 每次只做一个阶段/任务卡，先给主 Agent 可审阅 diff 和测试证据；不要一次性重写 `inline-09.js` 或四个适配器。
- 不用正则全局替换 `frontPipe`；必须按语义区分几何字段和水力结果。
- 不把总管塞进 `network.trunk` 或另建 `plot.trunk`，直到 D1/D8、模型校验、CAS 和组语义共同评审通过。
- 不硬删旧几何/本地存档；不清理用户存储；迁移必须可回滚并验证旧版本再打开再保存的结果。
- 不把合成测试或静态搜索描述成真实工程验收；不编辑/覆盖其他 Agent 未提交文件。
- 不新增独立页面；总管继续叠加在共用 CAD 画布上。
- 分区角度与总管行为按现有约定处理；不以本清单扩大角度重匹配范围。

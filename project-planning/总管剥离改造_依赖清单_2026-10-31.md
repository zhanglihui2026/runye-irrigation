## 0. 先分清两件事（最容易搞错）

代码里 `frontPipe` 有**两个完全不同的东西**，同名不同物。剥离只针对第 ①，第 ② 必须保留。

| 编号 | 形态 | 含义 | 出现在 | 处置 |
| --- | --- | --- | --- | --- |
| ① 几何折线 | `data.frontPipe = [{x,y},…]` | 总管在地面上的走向点列（米） | `inline-09` 生成 → `tlDiagramData` → 渲染/签章/DXF | **取消自动生成**，改由地图页提供 |
| ② 水力选型结果 | `r.frontPipe = {od,id,v}` | 按联合流量选出的总管管径/流速 | `computeThreeLevel()` 返回值 | **原样保留**，只是长度来源要换 |

> 判据：带 `.od` / `.id` / `.v` 的是 ②；带 `.length` / `[0].x` 的是 ①。

## 3. 拆分顺序（建议，务必按序）

**Step 1 · 先加空值守卫（不改行为，纯防御）**
上面标「会抛」的 7 处（`4196 / 4220 / 4231 / 4246 / 4250 / 4287 / 4295`）全部补 `if (frontPipe && frontPipe.length >= 2)`。
> 此时行为完全不变，但为 Step 2 铺路。**单独一版可回归**。

**Step 2 · 关掉兜底自动生成**
只动 `4152-4160` 这段兜底 + `4098/4111/4130` 三个分支入口，让 `frontPipe` 产出 `null`。
> 回归重点：材料表「总管」行是否空、水力是否仍能算（用 `tl_frontPipeLen` 保底）、DXF 是否缺层。

**Step 3 · 换数据源**
给 `tlDiagramData` 增加地图页总管的注入通道（`window.RunyeBridge.setTrunk()` 之类），渲染/统计/水力全部改为「有地图总管就用它，没有就用长度输入兜底」。

**Step 4 · 下线相关交互**
- 总管三通拖动（`tl-workspace.js:290` + v568 相关）
- 水源热区定位（`plot-editor.js:3489`）
- `tl_frontPipeLen` 输入框（`index.html:2292`）改为只读或隐藏

## 4. 风险清单

| 风险 | 说明 |
| --- | --- |
| **静默回滚** | `drawing-design-model.validate` 对 `network` 字段是硬校验，改结构若漏改 adapter，表现为「一刷新就没了」且只在 console 一行 warn（锁定面积失效同源） |
| **总管几何被分区页编辑抹掉**（2026-10-31 新增，见任务清单 v2 §2.5） | L2 提交走 `mod/inline-12.js:140-146` 的 `updatePlot`，`target.network = …` 是**整块替换**；`core/drawing-design-legacy-adapter.js:62-78/160-177` 只映射固定 8 键。总管字段若放进 `network` 而某个 adapter 没同步，用户每拖一次分区线总管就消失一次，且不报错 |
| **`frontPipe` 空导致整图不生成** | `inline-09.js:1003` 有 `if(!d.frontPipe \|\| d.frontPipe.length<2 …) return EMPTY;` —— 内部计算路径会直接放弃整张图，**必须同步放宽** |
| **材料表对不上** | 总管长度/管径是材料汇总的输入项，停产前要保证「来源」先接上，否则材料表会少一项 |
| **坐标系统一** | 地图页经纬度 → 米制投影必须与二级同一套（地块中心或固定原点），错位是严重 bug |
| **旧存档兼容** | 历史方案里已有 `frontPipe` 几何，读入时不能报错，且要决定「显示为参考底网」还是「直接忽略」 |

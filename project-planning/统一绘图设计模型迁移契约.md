# 统一绘图设计模型迁移契约

状态：迁移实施中（纯模型与转换已建立；组级总管、成员槽切换、逐块分区模式/角度与切线编辑及整组布管/清管已接入规范事务；二级逐块撤销和整组多成员撤销写回规范成员事务，工程级撤销仍恢复完整工程快照；组及单地块新存档携带规范模型并投影旧字段）  
范围：地块分区（二级）与管路规划/施工简图（三级）共用的工程绘图数据  
目标：用一份按地块归属的权威设计模型支撑不同绘图界面；不把两个绘图引擎、页面交互或图纸展示状态强行合成一个模块。

## 为什么要改

当前二级 `ppState` 同时保存地块环、分区角度和切线、手绘主管/支管、水源阀门、视口缩放平移、撤销及临时拖动状态。三级 `tlDiagramData` 则是由当前输入和分区结果生成的米制几何快照；自动管线编辑、手工管线、节点和位置覆盖又分别保存在三级工作区模块中。`inline-12.js` 保存工程时需要分别写入并按顺序恢复 `pipePlan`、`tlDiagramData`、编辑覆盖和辅助位置状态。

这种分离曾保护了不同绘图功能，但也留下多个可被误认为“当前设计”的状态副本。切页、改分区、生成施工图、恢复工程或逐块成组时，必须额外处理快照新旧、地块归属和编辑覆盖签名。因此统一权威模型有必要；立即删除旧接口或把生成快照也改成可写模型则有明显回归风险。

## 目标边界

1. 一个工程只有一个权威 `drawingDesign`；二级与三级不再各自持有可独立成为设计真相的副本。
2. 绘图引擎仍可分别存在。二级编辑器与三级绘图/施工视图是同一设计模型的不同编辑器或投影，不要求共用同一套 DOM、Canvas/SVG 渲染器。
3. 地块边界是真实工程坐标中的固定输入。设计分区角度只旋转分区网格相对边界的方向；不得旋转或改写边界点。最终出图为排版美观而旋转时，只能属于三级输出展示变换。
4. 每块地独立保存分区与管路设计。多地块组保存成员引用和组级总管；组级操作不能重算或覆盖成员地块的边界、分区、主管/支管设计。
5. 屏幕视口、选中项、悬停、拖动草稿、绘图工具模式等短暂 UI 状态不属于工程设计模型，不跨视图伪装成工程数据。
6. 水力计算结果、材料汇总和图纸 SVG/DXF 属于可追溯的派生结果或输出。必须由模型修订号/几何签名识别是否仍与当前设计相符，不能反向覆盖设计输入。

## 规范对象形状（提案）

```js
{
  schema: 'runye-drawing-design',
  version: 1,
  projectId: '...',
  revision: 12,
  plots: [{
    plotId: '...',
    geometry: {
      coordinateSystem: 'local-meter',
      frameId: '...',
      boundary: [{ x: 0, y: 0 }],
      sourceRef: { plotLibraryId: '...', geometryRevision: '...' }
    },
    partition: {
      angleDeg: 7.5,
      mode: 'auto',
      xCuts: [], yCuts: [],
      stepOverrides: { x: {}, y: {} },
      areaLocked: false
    },
    network: {
      mainPipes: [], branchPipes: [], subBranchPipes: [],
      source: null, valves: [],
      ids: { main: [], branch: [], subbranch: [] },
      hidden: { main: {}, branch: {}, subbranch: {} }
    },
    generated: {
      sourceRevision: 12,
      geometrySignature: '...',
      level3Geometry: null
    }
  }],
  groups: [{
    groupId: '...',
    memberPlotIds: ['...'],
    trunkNetwork: { pipes: [], nodes: [], source: null }
  }]
}
```

这是字段所有权提案，不是要求一次性照抄当前字段名。实现时必须明确坐标基准及投影变换；`generated.level3Geometry` 是缓存/生成快照，只有 `sourceRevision` 与当前修订一致时可用。成员排序、轮灌、水力输入等业务字段在接入前按现有真实消费者核对，不得仅凭示意结构迁移或丢弃。

### 字段归属

| 数据 | 权威归属 | 规则 |
|---|---|---|
| 地块边界与坐标基准 | `plots[].geometry` | 不因切页、旋转分区或生成图纸而变；边界更新须带新几何修订 |
| 分区网格角度/切线/阶梯覆盖 | `plots[].partition` | 角度是分区方向；切线坐标须能映射回固定地块坐标 |
| 二级手绘管线与管件 | `plots[].network` | 以所属 `plotId` 保存；多地块组不共享子块管线数组 |
| 三级自动几何 | `plots[].generated` | 从分区、参数和管线设计派生；不能作为平行权威输入 |
| 三级手工修订 | 归入设计网络或有明确 owner 的覆盖事务 | 先按“参与水力/材料/图面”的现有契约分类；几何签名不匹配必须丢弃或提示，不能静默套用 |
| 组级总管 | `groups[].trunkNetwork` | 独立于每个成员内部管网；组成员设计不得被总管操作重置 |
| 视口、工具状态、撤销栈 | 编辑器/会话 UI 状态 | 不参与设计修订，不写进 canonical design；如需恢复 UI 偏好，单独存 UI namespace |
| 水力结果、材料表、图纸导出 | 派生/输出层 | 绑定设计修订与输入签名；过期时重算，不反向覆盖几何源数据 |

## 接口迁移规则

- 新增单一 `RyDrawingDesignStore`（名称可调整）作为绘图设计读写所有者，提供按 `projectId`、`plotId` 读取、事务更新、校验、修订递增和迁移状态查询的窄接口。
- 更新采用显式事务：传入目标地块 ID、预期修订和变更函数/操作；修订不匹配返回冲突，不把旧页面快照整对象覆盖新状态。
- `window.ppGetState`、`window.ppSetState`、`window.RunyeBridge`、`window.tlDiagramData` 在迁移期保留兼容适配器；适配器只能映射到同一个 Store，禁止同时维护一份影子权威状态。
- 三级自动生成结果从 canonical design 读取输入，写入受修订签名保护的派生缓存；只有明确的用户编辑命令才可提交设计事务。
- 导入旧工程先转换到内存副本并完整校验；不认识的字段必须保留在兼容区或拒绝迁移，不能静默清空。旧快照只有在地块 ID、边界/坐标基准与签名校验成功后才能归入目标地块。
- 迁移期间如 canonical 与旧格式不一致，优先保护用户最近一次明确编辑；无法证明先后关系时停止写入并报告冲突，不采用“最后加载者胜出”。

## 优缺点与风险判断

### 改为统一权威模型

优点：每块地只有一个可识别的设计真相；切页和恢复减少整对象复制；分区方向、管线和组关系能按地块明确归属；生成快照有修订来源，可避免旧图覆盖新设计；未来增加图纸视图时复用同一设计契约。

成本与风险：旧存档字段很多且存在历史版本；坐标从二级、三级和地图投影之间转换，单位或原点处理错误会造成几何偏移；旧 UI 通过全局变量直接读写，兼容期会短暂增加适配代码；多地块逐块继承、手工编辑签名、水力/材料口径和恢复时序都需要回归验证。该迁移不能承诺“零风险”，需要分阶段发布并保留回滚路径。

### 保留两份状态长期并行

优点：改动少，旧流程和存档暂时不受迁移影响；两个编辑器可独立演进。

代价：新功能仍须决定写二级、三级还是两边；快照同步、修订判定和跨页面恢复复杂度继续累积；成组切块、分区微调和编辑器切换更容易出现数据不同步。适合作为短期止损方案，不适合作为长期架构。

结论：**值得迁移；采用一个权威数据模型、多个受控视图/编辑器，而不是合并两套绘图引擎。**

### 第 1 阶段：契约与当前行为基线（本文件）

- 核实二级设计、三级生成快照、工作区编辑层、工程保存恢复和组成员存档的所有写入者/读取者。
- 给边界、分区、网络、生成缓存、组总管、UI 状态分别建立测试夹具和可比对的序列化样例。
- 未完成前不删除旧状态、旧键或兼容 API。

### 第 2 阶段：纯模型与转换适配器

- 已新增 `core/drawing-design-model.js`：定义版本化绘图模型、边界/分区/管网/组成员结构校验、克隆、乐观修订事务和按地块修订递增。它已进入主页加载链，目前只由多地块组总管和有限组成员提交路径调用；单地块编辑与三级生成/编辑仍未接管。
- 已新增 `core/drawing-design-legacy-adapter.js`：只转换单地块旧快照；要求调用方显式提供工程 ID、地块 ID 和坐标框架 ID；地块/二级边界冲突、地块归属冲突及组快照会失败关闭。旧快照、编辑器视口与三级派生数据保留在模型外的迁移信封中；导出只生成兼容快照，不写存储或页面状态，并清空过期 SVG 缓存。
- 已新增 `core/drawing-design-group-adapter.js`：将显式绑定的组快照转换为成员地块与组级总管模型，校验成员身份/槽位几何和重复总管快照；每个成员块的三级生成物与编辑覆盖绑定到对应成员地块修订，并保留逐块会话态和旧块快照。没有稳定成员归属的项目级三级状态失败关闭；导出要求成员顺序、成员边界、几何签名及总管字段可映射。新组快照恢复以经校验的规范模型为来源，再投影回兼容旧状态；缺少规范字段的旧组存档继续导入旧格式，规范字段无效或无法投影时失败关闭。有限组写路径通过 `updateGroup` 或 `updatePlot` 提交。
- 已新增 `core/drawing-design-level3-adapter.js`：按自动/手工编辑器当前相同的 `[frontPipe, mainPipes, branchPipes, valves, poly]` 序列口径计算几何签名；导入三级生成几何、手工管线/配件、自动改长/配件/平移/遮蔽、节点与连线及手工分组，并把会话态改径留在迁移信封。单地块与组适配器把三级生成物绑定到对应绘图对象修订；导出要求修订和几何签名仍匹配，旧快照不能跨修订复活。
- 纯模型事务现为组记录也维护独立修订号，使组级总管或三级派生/编辑数据变化不会误增成员地块修订。单地块与三级适配器尚未接入页面；现有组事务只覆盖列出的写路径，撤销和未迁移存档路径仍依赖兼容快照。
- 地块修订号现明确表示二级源设计修订：修改 `generated` 或 `network.level3Edits` 不推进该修订，避免三级结果因写入自身而立即失效；边界、分区或二级管网改变仍推进修订。组级总修订仍记录事务变化。
- 单地块三级节点/连线、手工管线与自动编辑的用户写入现在尝试写入规范事务；工作区把连续变更合并后提交，节点拖动结束提交最终桩号。提交要求当前地块 ID、二级设计字段、生成几何签名及生成输入签名有效。组态、恢复通知、会话态改径、旧无签名生成物和已过期快照不进入此写路径。
- 单地块存档恢复在写地块锚点前检查带签名的三级图是否仍对应存档设计输入；失配时拒绝整份载入，旧无签名档继续兼容。保存合并 canonical 状态时，生成物的 `sourceRevision` 回填为事务实际结果的地块修订，避免三级编辑仅改变总修订时误判为过期。
- 单地块确认分区角度现先核对 canonical 与编辑前 L2 设计，再经 `updatePlot` 提交；提交拒绝时恢复编辑前槽。预览不写入；没有 canonical 的初次/旧项目继续走兼容路径。
- 单地块自动布管现捕获生成前 L2 前像，布管完成后核对并经 `updatePlot` 提交；规范事务拒绝时恢复前像并重绘，组内逐块和整组路径继续使用各自事务桥。
- 单地块清除管路现将管线、水源、阀门、遮蔽与管线标识作为一次 L2 事务提交；拒绝时恢复旧槽并刷新简图和材料，组态清除仍按成员批次提交。
- 单地块确认重新分区将面积锁解除、切线重置和管网清空合并提交；事务拒绝时恢复完整前像，组内逐块使用成员提交路径。
- 单地块自动划分开关现先提交canonical分区模式，再写共享默认值；提交拒绝时恢复原模式且不改默认值，组内逐块仍提交成员事务。开关变化进入本地撤销历史，撤销恢复canonical模式、界面与共享默认值。
- 单地块放置水源和阀门现捕获二级前像并分别提交canonical管网；拒绝时恢复原槽，阀门路径同时刷新材料显示，组内仍由成员事务处理。
- 单地块切线拖动结束（包括三级边界桥）现以拖动前分区为前像提交canonical；拖动预览不写入，提交失败时恢复分区并重算下游。
- 单地块三级阶梯切口拖动结束时提交规范三级派生状态；规范提交拒绝则恢复拖动前的阶梯覆盖和几何快照，组内逐块继续走成员事务。
- 单地块面积锁定、重置网格和切线微调通过二级规范事务提交；整组总览只读，不直接清除合并网格状态。
- 二级本地撤销将恢复后的单地块设计提交到规范模型、组内逐块提交到成员槽；失败时不消费撤销项并恢复操作前状态。工程级撤销仍由完整工程快照路径恢复。
- 工程级快照恢复先在局部副本中校验并投影规范模型；仅当当前地块锚点写入成功后才替换运行时单地块canonical状态。旧格式或组快照清除单地块canonical影子，避免锚点写入失败造成规范模型与页面仍处于恢复前状态不一致。
- 多地块组快照在工程加载器写地块锚点前执行纯预检；规范组快照须通过成员身份绑定、兼容字段投影及规范再导入，失败则整份工程快照不进入后续状态写入。
- 组适配器支持外层 `groupPlan` 包装时，导入与导出都会同时检查包装层和内层计划是否含有无稳定成员归属的三级状态；任一层存在此类状态即拒绝，避免内层项目级数据绕过失败关闭。
- 规范模型的地块、组、成员引用、网络及管线 ID 数组必须连续无空槽；边界环、分区切线和切线快照坐标还须元素有限。组适配器逐索引校验成员边界，避免稀疏数组通过会跳过空槽的数组迭代校验。
- 单地块管线隐藏/显示属于网络设计状态，点击切换现按前像调用规范事务；拒绝时恢复旧显隐映射，组内逐块沿用成员槽事务。
- 规范写入拒绝后撤销栈不应保留失败编辑对应的前像；Undo 自身写入失败则保留待撤销项，三级阶梯拖动与无历史复位分别处理。
- `mod/inline-29.js` 的组级总管管径、建议管径、画线收线、删除与清空现先经 `updateGroup` 乐观修订事务，再由组适配器生成旧存档兼容投影；投影失败时拒绝该次操作。`groupPlan` 仍承载工程与撤销兼容快照，新组恢复优先读取其 `canonicalDrawingDesign` 并重建兼容字段；其他成员地块写路径和单地块持久化权威尚未迁移。
- `mod/inline-12.js` 的单地块工程存档在非组模式、存在稳定地块 ID 且旧字段可无损导入时附带 `canonicalDrawingDesign`；连续编辑复用同一地块的规范修订事务。每地块 L2 继承档也携带该模型。`mod/plot-editor.js` 成组继承时优先验证模型身份并投影兼容字段，再按既有成员环校验、平移和裁切；规范模型存在但校验/投影失败时拒绝该档案候选，不退回它自己的旧字段。没有规范字段的历史档案仍走原兼容路径。页面编辑仍以旧全局状态为运行时入口，因此此步建立了规范存档来源但尚未让所有单地块写操作直接提交模型事务。
- `mod/plot-editor.js` 在逐块切换、切换整组模式和生成组图前捕获当前成员槽；水源和阀门落点也在逐块态即时提交成员槽。`mod/inline-29.js` 使用旧槽快照构造规范前像，并在规范字段变化时按成员 `plotId` 经 `updatePlot` 提交，再仅投影该成员槽。被编辑成员的旧三级派生状态随二级字段变化失效，组级总管和其他成员修订保持不变；旧 `ge.slots` 仍承载持久化和恢复。
- 整组自动布管和清除管路现先对受影响成员槽构造副本，在规范模型上逐成员提交 `updatePlot` 候选；全部更新和组适配器投影成功后才一次写回 `ge.slots`，失败时保留原成员数据和合并视图。
- 逐块分区角度在预览期间只更新编辑器状态；用户确认角度、拖动/微调切线或重分区时捕获当前成员槽并经 `updatePlot` 提交，事务或兼容投影失败则恢复已保存槽并刷新图面。
- 逐块自动划分开关先经 `updatePlot` 提交成员分区模式，成功后才更新界面和 `runye_zone_auto` 共享默认值；提交失败不改变模式或默认值，操作前状态进入本地撤销栈。
- 仍需补充模型、单地块/多地块往返和失效边界的回归夹具，并核对生成几何输入签名与现有水力/材料消费者的绑定口径；本轮总管及成员槽运行时事务尚未完成独立浏览器验收。
- 添加新旧往返测试：边界精确保持，分区方向/切线保持，内部主管支管保持，生成快照可按修订失效，组总管与子块隔离。
- 新写路径只替换明确的组编辑提交；其余路径仍按各阶段计划渐进接入，且存档权威尚未切换。

### 第 3 阶段：逐条写路径迁移

- 组级总管、成员槽切换、逐块分区模式/角度与主要切线编辑及整组布管/清管已接入规范事务：总管用 `updateGroup`，成员设计用 `updatePlot`；旧 `trunk` / `edit.trunk*` 和 `ge.slots` 接收兼容投影。新组快照持久化规范模型并在恢复时以其重建兼容字段，缺少规范字段的历史组快照仍可导入。批量成员更新全部成功且可投影后才应用；导入、修订或投影不能证明时拒绝对应编辑。
- 先迁移分区编辑和二级明确的工程编辑动作，再迁移三级生成输入及用户手工编辑提交。
- 每次只将一种写操作切到 Store；旧全局 API 改为薄适配器。运行新旧结果对照，发现差异即回滚该操作。
- 多地块组和单地块工程保存/恢复携带 canonical 模型字段并保留旧字段兼容；仍需完成旧版工程导入、存档恢复及跨地块保护验收，并将单地块编辑写操作迁移为规范事务。

### 第 4 阶段：组规划与去重

- 组只保存成员 ID 与组级总管；逐块分区和内部管路按成员 ID 更新。
- 逐块切换、组内编辑、组级总管编辑以及成组传递均验证成员设计修订不变，除被明确编辑的对象外不发生变化。
- 统计旧字段消费者；当无生产读写路径、兼容导入测试通过后，才停写并在后续版本移除旧存档镜像。

## 必须验收的行为

1. 同一个地块在二级微调分区角度后，地块边界坐标逐点不变，三级投影方向与新分区一致。
2. 切换二级/三级视图、打开/关闭工具栏、缩放平移画布，不改变 canonical design revision。
3. 三级重新生成只更新派生几何；旧异步生成结果或旧存档不能覆盖更新后的分区/管线设计。
4. 多地块成员逐块已分区、已布主管/支管后成组；成组总览与绘制总管不改变任何成员边界、分区、管线或成员修订。
5. A/B 两块交替编辑和恢复，任何 A 状态都不能写入 B；缺失或重复地块 ID 必须失败关闭。
6. 当前工程、旧版工程、撤销/恢复以及既有人工/自动三级编辑均通过兼容验收；无效签名的覆盖不得静默复活。
7. 至少有可自动运行的纯模型/存档/成组回归测试和单独标明环境的真实浏览器跨视图验收。

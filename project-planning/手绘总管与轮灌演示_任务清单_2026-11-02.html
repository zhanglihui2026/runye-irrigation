一、最终目标（用户原话口径）

在地图上可以从水源画总管，之后一直连接到主管的节点上，最后形成闭环，形成一条完整的水路，让在线地图可以实现轮灌区切换的动画演示。

「闭环」口径已确认：指贯通无断点——从水源到每个轮灌区的支管全部连通；不是水力环形管网。

二、已拍板的决策（7 项）

#决策内容与理由
1节点定位权威 = 主管签名 + 沿线距离 s（米）坐标全部派生不入库：图面坐标（米）与地图经纬度均由参数现算。重生成/旋转角度后按 s 重挂节点不丢。
2两边同体 = 同一份参数、两条派生渲染分区与管路页与在线地图读同一份参数，不存在"同步"问题——根本不存两份数据。
3职责划分 = 方案 A设计页 = 插入/删除节点唯一入口 + undo 归属；地图 = 拖动微调 + 定位面板 + 手绘吸附。插节点属设计行为，设计页是它的家。
4地图端不加「插入节点」按钮避免双入口认知混乱。若日后"看着地图想插节点"高频发生，可按方案 B（三道闸门）补加——加得回去，收回来难。
5捕捉优先级：点目标优先、线段兜底10px 内有预生成点（阀门/驳接点等 7 类）吸点；无点才吸主管/总管线段垂足。Shift 正交仍优先于一切捕捉（v852 语义不变）。
6重生成兜底：geoKey 失配 → 回退默认位 + 图面提示主管签名对不上（如分区数变化导致主管消失）时宁缺不错（v835 口径）。同款先例：改径重算 tlPipeOdOverride（inline-09:178）。
7「闭环」= 贯通无断点从水源到每个轮灌区支管全连通；非环形管网（若指环形管网需另立专项）。

七、风险与守卫

  1. 防乱三道闸门（若未来按方案 B 开地图端插入）：①前置条件闸（无分区管路数据时按钮禁用）②同链提交闸（同一事务入口，绝不另存一份）③反馈闸（提示"已在设计页节点集中添加，可在设计页撤销"）。
  2. 并行会话冲突：mod/online-map.js 当前混有并行会话未提交改动（底图滴灌带策略）——步骤 2 动工前必须确认其已提交落地，避免混提交。
  3. 双轨期写路径：节点事务提交是新写路径，必须直接走 canonical 事务链（revision 单调 + CAS），不碰旧字段写法——与权威切换批次 E 不冲突、方向一致。
  4. 投影保真：geoBridge 失败（地块不一致 / ±y 对不上）时节点在地图端静默跳过——宁可少吸，不吸错位。
  5. 重生成失配：主管签名对不上时节点回退默认位 + 图面提示，不静默错挂。
  6. 落点/预览共用：拖动预览与松手落点必须走同一个投影函数（v852 教训：两边各写一份迟早漂移）。

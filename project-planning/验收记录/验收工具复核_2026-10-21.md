## 2026-10-22 续核：系统图参数与支管改径

本轮没有修改产品代码，也没有覆盖旧等价性基线。

1. **先纠正比较对象。** 等价性快照中的 `r` 是 `window._r`（二级计算对象），不是三级 `computeThreeLevel()` 的结果。不能用它与三级系统图的扬程/功率作差异判据。
2. **核对系统图实际取值链。** `mod/inline-09.js::tlBuildSysUrl()` 在生成 URL 时调用 `computeThreeLevel()`，再交给 `window.tlFigParamLines()` 格式化流量、扬程、功率和图面管径。隔离 Edge 浏览器实测中，三级计算返回 `pumpHead=33.7755 m`、`pumpPower=18.8797 kW`，`tlFigParamLines` 与系统图 URL 均显示 `33.8 m`、`18.9 kW`；本次样例的流量和三类管径也一致。该样例证明当前传参取数链一致，不代表所有历史快照都已解释。
3. **复验固定工况改径。** `node scripts/gate.cjs --filter=pump --strict` 于 2026-10-22 在当前工作树通过（PASS 1 / FAIL 0 / SKIPPED 0）。现有 Playwright + Edge 场景固定其他输入和图面，直接比较支管 Ø140 与 Ø110，断言流量不变且水损、最不利路径损失、扬程、轴功率上升；刷新恢复、撤销覆盖和界面显示断言也通过，页面无运行时异常。
4. **历史 `32.4 → 32.1 m` 仍属待复现差异。** 旧、新采样里的 `window._r` 相同，但它不是这组三级数值的计算来源；两次快照没有保存三级计算的完整输入、图面路径和管径覆盖快照。现有提交中与两次采样间隔对应的变更未改动三级水头计算/系统图取值逻辑。故不能据此认定公式错，也不能宣称已找出差值成因。保留旧基线；若要精确追因，需用同一图面、参数和覆盖状态连续重采两次三级结果与 URL。

**本次结论：** 用户此前提出的“固定条件下支管改细但扬程下降”已被当前自动回归明确排除；当前系统图 URL 与三级计算一致。系统图历史样本的 0.3 m 偏差为未复现、缺少输入证据的旧差异，暂不整改、不重置基线。N04 尚未整体关闭，支管根数/敷设边数组合及材料量/接入段仍需按任务清单中的有限范围验收。

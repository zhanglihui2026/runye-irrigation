## 一、协作规则与责任

项目只有两个执行者：我负责统一数据契约、共享文件接入、跨模块集成、回归与最终验收；另一位**执行 Agent**依次负责 A、B、C、D 四个工作包。A/B/C/D 是任务编号，不代表四位 agent。每包完成后先由我验收，用户查看阶段成果，再进入下一包。

| 工作包 | 负责人 | 独占交付区 | 共享文件写入 |
|---|---|---|---|
| A 底图与坐标 | 执行 Agent | 新建 `terrain/mountain-basemap-*`、对应专用测试与样本 | `terrain/index.html`、`terrain/terrain-ui.js`、`terrain/terrain-core.js` 由我接入 |
| B 不规则分区几何 | 执行 Agent | 新建 `terrain/mountain-zone-geometry*`、对应专用测试与样本 | 交互页和主站模型由我接入 |
| C 管网与水力 | 执行 Agent | 新建纯计算/验证模块与专用测试，优先复用已有水力核心 | `mod/online-map.js`、`mod/inline-09.js`、水力页面由我接入 |
| D 图面与导出 | 执行 Agent | 新建山地图面布局、图例、导出适配模块与专用测试 | `runye-dxf.js`、`index.html`、主 CSS 与 PWA 缓存由我接入 |
| 集成 | 我 | 契约、适配器、主页面交互、存储迁移、合并与验收记录 | 唯一负责跨包共享文件 |

以上文件名是**拟定所有权**，不是已存在接口。执行 Agent 开工时先复核当前源码和 `AGENTS.md`，若现有能力适合复用，应给出理由，不为遵守拟定文件名而重复造轮子。独占区以各工作包创建的文件为准；需要改共享文件时提交最小补丁建议，由我统一落地。执行 Agent 使用独立 `codex/mountain-execution` 分支或 worktree，按阶段提交；不得清理、覆盖、暂存或提交其他人的改动。开始前记录基线 commit、工作树状态和本阶段要改的文件。不得把现有脏工作树直接当作干净基线复制后提交。

### 统一交付格式

执行 Agent 每完成一个工作包就交付：①改动文件清单和 commit；②接口说明与数据样例；③测试命令及原始结果；④浏览器操作步骤和截图（涉及 UI 时）；⑤未覆盖条件、工程风险与回退方式。不能以“按钮可点”“图上有线”“单元测试通过”单独声称阶段完成。未经用户要求不部署、不 push、不改生产数据。

任何对象都应保留稳定 ID、地块身份、坐标参考、单位、来源与修订信息。面积计算使用未舍入平方米，亩数只用于显示。工程数据只有在坐标与参数可追溯、校验通过时进入水力计算；示意底图或缺失高程不得产出假精确扬程。

## 三、阶段 0：我先冻结的公共契约

**我的任务**：调查当前主站规范绘图模型、地块库存储、地形页 `loadState/saveState` 白名单、`sendHome()` 交接和地图/水力/导出消费链。产出单独的接口契约文档和黄金样本；下面字段只是必须覆盖的概念，不是允许 agent 自行定版的 JSON Schema。

- 坐标：明确底图原始 CRS、经纬度、世界米坐标、地形 SVG 显示坐标间的变换及精度；未知 CRS 的草稿与工程模式分离。
- 地块：园区外环、洞、道路/水体/禁布区各有对象身份；分区引用所属地块和修订。
- 分区：唯一 ID、名称、有效面、未舍入面积、显示亩数、目标面积、阀门引用、状态；共享边的权威维护策略。
- 管网：水源、设备、节点、管段、分区入口及连接关系；画线几何与拓扑分开，不能靠像素重合推断连通。
- 计算：轮灌组、设计流量、流速区间、候选规格、损失、入口/末端压力、扬程、计算版本、输入来源和不足项。
- 图面：标注位置、可见性、线型、图例、底图引用、输出比例与纸张；图面覆写不得悄悄改设计数据。
- 迁移：旧地块和旧工程仍能读取；新山地字段失效时拒绝写入并保留原工程；保存恢复遵循现有修订/冲突约束。

**阶段 0 验收**：契约 v0.1 已提供 4 类黄金样本（凹面、带洞/禁布区、完整轮灌网络、缺参数）和预期错误码；执行 Agent 在相应工作包中以可执行 fixture 复核。第一阶段暂按“在线地图 + 可校准图片”、手绘闭合分区为主、切割为辅，以及先可信分区和可编辑总图推进。若用户调整产品选择，先修契约再接入主站。

## 九、阶段 5：合并、验收与停止条件

我按 A、B、阶段 2、C、D 的依赖顺序集成。每一步先核对执行 Agent 的改动范围、接口样本和测试，再把所需共享文件接入主站；冲突由我按统一契约解决，不把执行 Agent 的版本直接覆盖正在进行的其他主程序改动。所有新增主页资源必须检查 `index.html` 装配顺序、`sw.js` 缓存/版本和发布引用，运行仓库现有 `npm run check`、`npm test` 及针对新增功能的浏览器操作验证。只在必要时补针对真实风险的测试。

最终用户验收按下列五条真实路径逐项签字：

1. **数据来源**：在带坐标底图或通过控制点校准的图像上定位园区；原始来源、CRS 和误差可见。
2. **不规则分区**：手绘/切割、编辑、保存、刷新、回传后，至少 8 个小区仍在正确位置且面积守恒。
3. **管网**：水源经总管、主管、阀门到支管有可验证拓扑；故意断开时能指出具体断点。
4. **水力**：轮灌组切换能显示相应分区流量和可信扬程/未校核原因；总管路由生成后给出带依据的建议管径。
5. **图纸**：PDF 与参照图逐项对照、文字可读；DXF 图层、坐标、单位和可编辑对象经重新导入核验。

验收记录必须列出环境、commit、输入样本、操作步骤、预期/实际、截图或导出文件、未通过项。任何一项未通过就保留该阶段为“待修复”，不能用后续阶段的功能掩盖。线上发布另设独立验收，不以本地成功等同线上成功。

# 山地灌溉图阶段 0 数据契约 v0.1

状态：**并行开发接口冻结，主站持久化适配待阶段 2 验收**。  
适用范围：唯一执行 Agent 依次完成的底图与坐标 A、分区几何 B、管网水力 C、图面导出 D 四个工作包的模块间输入输出；A/B/C/D 不是不同 agent。  
基线：`573280a`；调查日期 2026-11-04。主程序另有并行修改，集成前必须复核最新源码。  
参照：[分工与阶段验收](山地灌溉图复刻_多Agent分工与阶段验收_2026-11-04.md)及[产品讨论稿](任务书_山地槟榔园灌溉规划图复刻_讨论稿_2026-11-04.md)。

## 1. 冻结原则

1. A/B/C/D 以本文交换**纯数据和纯函数结果**。`index.html`、地形页 UI、旧绘图模型、地块库、跨页桥和 PWA 装配均由集成负责人修改。工作包不得私自把新字段写进旧 `partitionCuts`、`runye_network_layout` 或旧 `runye-drawing-design/v1`。
2. 基础几何统一为局部右手平面米坐标：`x` 向东、`y` 向北；显示层可翻转/旋转，但不能改存储几何。坐标、长度、面积、流量、扬程分别使用 m、m²、m³/h、m。亩数仅显示，按 1 亩 = 666.67 m² 换算，不作为面积守恒依据。
3. 每个工程对象有稳定字符串 ID；引用按 ID 解析，不靠数组序号或肉眼重合。所有数值必须有限。不能修复的几何或引用错误，返回结构化错误，原工程保持原样。
4. `status` 必须区分 `draft`（可编辑但未校准/校核）、`geometry-valid`（几何有效）、`network-valid`（拓扑有效）、`hydraulics-verified`（参数齐全且已计算）。缺少依据时不可跳级。
5. 源数据、用户编辑与派生结果分开。水力、图面可从设计重算；设计字段变更后旧派生结果标记 `stale`，不得静默继续展示为当前值。

## 2. 山地设计交换对象

`runye-mountain-plan/v0.1` 是**工作包交换格式**，不是当前主站已支持的持久化 schema。示例中的字段为 v0.1 必备概念；未知可选字段保留，但不可决定工程计算。

```json
{
  "schema": "runye-mountain-plan",
  "version": "0.1",
  "projectId": "sample-project",
  "plotId": "sample-plot",
  "revision": 0,
  "status": "draft",
  "frame": {
    "id": "sample-local-frame",
    "units": "m",
    "sourceCrs": "LOCAL_TEST_METERS",
    "localToSource": [1, 0, 0, 1, 0, 0],
    "engineeringEligible": false
  },
  "basemap": {
    "kind": "none",
    "sourceId": null,
    "crs": null,
    "calibration": { "status": "not-calibrated", "rmsMeters": null, "maxMeters": null }
  },
  "site": {
    "boundary": { "outer": [[0, 0], [300, 0], [300, 200], [0, 200]], "holes": [] },
    "features": []
  },
  "zones": [],
  "devices": [],
  "network": { "nodes": [], "segments": [], "zoneInlets": [] },
  "operation": { "groups": [], "agronomy": null, "designLimits": null },
  "drawing": { "annotations": [], "visibleLayers": [] }
}
```

### 2.1 坐标框架与底图 A

- `localToSource=[a,b,c,d,tx,ty]` 定义 `sourceX=a*x+c*y+tx`，`sourceY=b*x+d*y+ty`。A 须提供正反变换、可逆性检查与校准误差；数组不是 SVG matrix 的默认替代，符号顺序以此式为准。
- `sourceCrs` 必须是明确可识别的真实坐标参考，或 `LOCAL_TEST_METERS`（仅测试）。不能仅写“CGCS2000”却不知道投影带、轴、单位及原点。真实工程对象需 `engineeringEligible=true` 且基于证据验证。
- `basemap.kind` 为 `online-map`、`georeferenced-raster`、`calibrated-image` 或 `none`；`sourceId` 引用资产记录，不将大图 base64 放进设计 JSON。`calibration` 保存方法、控制点、残差、状态；图像只有像素位置时不得计算工程面积。
- `site.features` 每项 `{id,kind,geometry,source,locked}`。`kind` 至少包括 `road`、`water`、`building`、`exclude`；面与折线必须显式标明 geometry 类型。道路/水体是否计入排除面积由对象的 `excludeFromIrrigation` 确定，不能仅由颜色决定。

### 2.2 分区 B

- `zone`：`{id,name,polygon,targetAreaM2,locked,valveId,status}`。`polygon={outer:[[x,y],...],holes:[[[x,y],...],...]}`。环首尾不重复存点；方向由几何模块规范化。`areaM2` 由 B 计算返回，若保存快照附带显示缓存，读入时仍必须重算核验。
- 分区不得越出园区有效面、压住禁布区，也不得与其他已提交分区内部重叠。未分配剩余面允许存在，但要显式显示面积；“全部分完”需剩余面低于几何容差。
- `valveId` 可在画区阶段为 null；进入 `network-valid` 前必须指向本地有效设备/入口。目标面积不是自动吸附承诺；锁定区禁止更改几何。
- 几何模块返回 `{ok,value?,errors:[{code,objectId?,detail?}],metrics?}`。切割预览不改输入；提交只在确切两个有效子区、并集一致、不重叠、无碎片且面积守恒时成功。默认守恒门槛初值 `max(0.01 m², 原面积×1e-6)`，最终容差须由 B 在真实坐标范围下验证。

### 2.3 设备与管网 C

- `device`：`{id,kind,nodeId,properties}`；`kind` 至少 `reservoir`、`filter`、`pump`、`valve`。位置权威在 node，不复制第二套自由坐标。
- `network.nodes` 项：`{id,point:[x,y],kind,deviceId?}`。`segments` 项：`{id,kind,fromNodeId,toNodeId,vertices:[[x,y],...],material?,chosenOuterDiameterMm?,manualOverrideReason?}`；`kind` 为 `trunk`、`main`、`branch`、`lateral`。`vertices` 首末点必须与 `from/to` 节点在米制容差内一致；吸附成功后引用相同节点 ID。
- `zoneInlets` 项：`{zoneId,valveDeviceId,segmentId}`。仅有线相交或端点距离很近不等于连通。C 须识别水源到每区阀门和支管的真实路径、孤岛、重复接驳、错误方向/回路，并给出受影响区 ID。
- `operation.groups` 项：`{id,name,zoneIds:[...]}`。分区流量只能由已确认的种植/滴灌参数与组配置推算；手绘总管只有路径，管径由系统提出建议或由人工有记录地选定。
- C 的计算输出是单独的 `runye-mountain-hydraulics/v0.1`：`{designRevision,status,missingInputs,zoneRows,segmentRows,groupRows,requiredHeadM,method}`。每行保留输入依据、单位、建议/人工值及不足项。`designRevision` 不等于当前设计修订时输出 `stale`。

### 2.4 图面 D

- `drawing.annotations` 只保存 `{id,targetId,offsetMeters?,angleDeg?,visible?}` 等展示覆写；不能保存与分区或管段相矛盾的面积/直径文本。正式文字从当前有效模型和计算结果生成。
- 图面导出输入是山地设计 + 可选当前水力结果 + 底图资产引用。D 应返回 `runye-mountain-drawing/v0.1` 图层清单、布局结果、警告及 PDF/DXF 输出所需适配数据。需要真实高程或管径而未提供时标注“未校核”，不补零或猜测。
- PDF 纸张/比例、北针、标题栏、图例、标注避让属于展示层；DXF 单位为米，底图外部引用与否须随输出清单说明。不能把显示 SVG 当作工程拓扑权威。

## 3. 错误码与返回口径

纯模块至少覆盖以下机器可判断错误，UI 翻译为中文提示；允许增加更细错误码，不允许仅返回一个模糊的 `invalid`。

阶段 0 的可执行结构校验位于 `core/mountain-plan-contract.js`，浏览器使用 `window.RyMountainPlanContract.validate(plan, options)`；Node 测试通过 VM 装载同一文件。返回 `{ok, errors:[{code,at}]}`，不改传入对象。它核对 schema/版本、有限坐标、稠密数组、稳定 ID 与引用、管段端点和节点位置；默认端点容差为 0.01 m，可用 `options.endpointToleranceM` 覆盖。**它不负责**判断多边形自交/相交、面积守恒、真实 CRS 证据、拓扑连通或水力计算。这些仍分别由 A/B/C 完成，不能把结构校验通过当成工程验收。

| 错误码 | 触发条件 | 写入动作 |
|---|---|---|
| `unknown-crs` | 工程模式无可验证投影基准 | 拒绝工程写入；保留草稿 |
| `invalid-calibration` | 控制点不足、病态或误差超门槛 | 拒绝工程坐标；保留图像 |
| `invalid-ring` | 面自交、退化或坐标非有限 | 拒绝面提交 |
| `outside-site` | 分区越过园区有效面 | 拒绝分区提交 |
| `zone-overlap` | 两个已提交区内部重叠 | 拒绝分区提交 |
| `split-not-two-faces` | 切割未产生恰好两个有效面 | 拒绝切割提交 |
| `area-not-conserved` | 子面并集/面积与原面不一致 | 拒绝切割提交 |
| `unbound-zone-inlet` | 区没有可引用的阀门/支路 | 水力状态保持未校核 |
| `network-island` | 水源到某区无拓扑路径 | 列出受影响区；不算该区扬程 |
| `missing-hydraulic-input` | 流量、压力或高程依据不全 | 返回缺失字段，不给伪数值 |
| `revision-conflict` | 写入时工程/地块修订变化 | 原值不变，重新读取后再应用 |

## 4. 黄金样本（进入各工作包的共同输入）

执行 Agent 在对应工作包中把以下样本做成可执行 fixture，不必复制本文件文本为生产数据。详细坐标仅用于测试，不代表南坤项目的实测数据。

1. **G1 凹面与切割**：外环 `[[0,0],[100,0],[100,40],[60,40],[60,80],[0,80]]`，面积 6400 m²；切割线从 `[30,0]` 到 `[30,80]`。B 验证输出两有效面、总面积 6400 m²、交叠面积 0。
2. **G2 洞与禁布区**：园区外环 `[[0,0],[100,0],[100,100],[0,100]]`，洞 `[[40,40],[60,40],[60,60],[40,60]]`，有效面积 9600 m²。一个覆盖洞的候选分区必须裁除或拒绝，不可报 10000 m²。
3. **G3 八区完整管网**：外环 `[[0,0],[300,0],[300,200],[0,200]]`；上排 4 区、下排 4 区，每区 75×100 m，8 区合计 60000 m²。水源节点在 `[-30,100]`，总管接入 `[0,100]`，两条主管沿 `y=50` 和 `y=150`，各设 4 个阀门并连接支管。C 用稳定节点 ID 表示接点，G1–G4 与 G5–G8 可分轮灌；故意断开第二条主管后，仅下排 4 区显示孤岛。此样本的农业与高程数值须显式写作**合成测试输入**，不得作为真实工程参数。
4. **G4 缺参数**：复用 G3 拓扑，删除高程与滴头流量。拓扑仍可验，分区流量/扬程状态为未校核并列出缺项；D 输出图纸也必须保留“未校核”标识。

## 5. 与现行代码的映射和集成门槛

| 已核实的现行事实 | 阶段 2/3 处理要求 |
|---|---|
| `terrain/terrain-core.js` 的 `loadState/saveState` 只选择性读写 plots、elevations、mode、_unit、_plotRot | 集成时明确加入新版本字段、迁移、校验及容量失败恢复；仅在对象中新增属性不会自动持久化 |
| `terrain/terrain-ui.js` 的 `sendHome()` 当前回传 `sqm/mu/poly/subPlots/terrainProfile` | 新山地分区通过明确版本化桥接，目标读入成功后才消费；不得把新面偷偷当旧 `subPlots` |
| `core/drawing-design-model.js` v1 仅接受 `local-meter` 边界及 `angleDeg/xCuts/yCuts` 分区结构 | 山地对象先由独立模型/适配器承载，旧模型仍可读；是否扩展主 schema 由集成测试和迁移证明决定 |
| `core/plot-library-store.js` 写入按 revision 比较，`core/irrigation-data-store.js` 绑定当前地块 ID 与设计修订 | 山地回传必须带地块身份与预期修订；冲突不覆盖其他标签页或别的地块 |
| 现有 `mod/trunk-size.js` 已实现按分区面积/滴灌参数与轮灌组建议总管口径；`runye-hydraulics-core.js` 有管网水力计算 | C 先对照复用，不建立第二套互相矛盾的管径表或损失公式 |
| `runye-dxf.js` 从权威 SVG 与 `tlPlanView` 转 DXF，按实体层导出 | D 的山地图面需要独立层/坐标映射验证，不能只把新图画到屏幕上就视为 CAD 已支持 |

**合并门槛**：A/B 的纯模块须通过黄金样本；集成负责人完成真实浏览器画区、保存恢复、主站交接后，C 的水力结果才可称为端到端；D 的 PDF/DXF 需重新打开核验。当前主程序有并行修改，接入文件和调用顺序必须以合并当天源码重新验证。

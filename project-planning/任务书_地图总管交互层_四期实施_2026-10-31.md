## 1. 三个技术冲突：我的裁决建议

这三条不定就无法开工。我给出推荐值和理由，你只需要点头或否。

### 冲突 1 · 多干线要改 schema

**现状**（`mod/online-map.js:558`）：

```js
var trunk = { schema:1, source:'map', coordinateSystem:'GCJ-02',
              points:[[lat,lng],...], revision:n };
```

单段数组，`renderTrunkDraft()` 直接用它画一条 polyline；列表行读的时候硬判 `p.trunk.schema===1`（`:1602`）。

**推荐：升 v2，但下游"只取一条主干"**，不要把多干线一次性推给施工图。

```js
plot.trunk = {
  schema: 2,
  source: 'map',
  coordinateSystem: 'GCJ-02',
  revision: n,
  trunks: [
    { id:'T1', main:true,  points:[[lat,lng],...],
      params:{ material:'PE', dn:110, designFlow:0 } },
    { id:'T2', main:false, points:[...], params:{...} }
  ]
}
```

**为什么下游只取一条**：`mod/inline-09.js` 的施工图只有一根 `frontPipe`，`tlDiagramData.trunkSource` 是 `'map' | 'missing'` 二值（`:4627`）。一次性让施工图渲染多干线 = 重写布管算法 + 水力校核 + 材料清单，这是**另一个项目**，不是这一套任务书能收的。

**规则写死**：`pickMainTrunk(trunk)` = `trunks.find(t=>t.main)` ?? `trunks[0]` ?? `null`。四个下游全部改成调它，**行为与今天完全一致**（今天只有一条，取到的那条就是它）。

**v1 → v2 迁移只允许有一个入口**：`window.RyTrunkSchema.normalize(raw)`，放在新文件 `core/trunk-schema.js`（进 `sw.js` 的 CORE 名单）。读时归一、写时升 v2。绝不在四个读取方各写一份 `if(schema===1)`。

**备选（不推荐）**：保持 v1 单段，多干线用 `plot.trunks` 平行字段存。缺点：两个字段会不一致，且已有 5 个读取方都要判"用哪个"，等于把迁移成本挪到长期。

### 冲突 2 · 0.3 m 阈值

你说的是同一个 0.3 m 用在"捕捉"和"合并"两处。**在 zoom 16 下 1 px ≈ 1.2 m，0.3 m = 0.25 px**，物理上点不中。

**推荐拆成两个阈值**（沿用 `snapTolUnits` 的"像素→米"思路）：

| 用途 | 值 | 单位 | 理由 |
|---|---|---|---|
| 捕捉吸附（鼠标靠近候选点就吸过去） | **10 px** | 屏幕像素 | 手感值；与全站"手柄命中"口径同量级 |
| 拐点合并（两拐点几何上是否算同一个点） | **0.3 m** | 实地米 | 你要的语义，用于"拖拽后自动合并"和"打断/接合"判定 |
| 最短管段（小于则删点） | **0.5 m** | 实地米 | 已存在于 `saveTrunkToCurrentPlot` 的 `trunkLengthM>0.5` 校验，沿用 |

**关键**：捕捉判定必须在**投影坐标**里算（`map.latLngToContainerPoint` 后的像素距离），不要在经纬度里算米——经纬度 0.3 m 的换算随纬度变化，且 `map.distance` 每次调用都有开销，mousemove 里逐点算会掉帧。

### 冲突 3 · 状态栏"高差/流速"没数据源

`trunk.points` 只有 `[lat,lng]`，**没有高程**。流速要 `Q` 和 `D`，`D` 现在是成组页的 `#grTrunkDn`（`index.html:1080`），单地块总管根本没有管径。

**推荐：缺数据就显示 `—`，绝不显示假 0**。理由：状态栏一旦写 `高差：0.00 m`，用户会拿它当真值去做水力判断，而 0 高差会让沿程损失算错方向。宁可空。

具体口径：

| 字段 | 数据源 | 缺省 |
|---|---|---|
| `总管：` | `trunk.trunks[i].id`（如 `T1`）；无总管 → `—` | `—` |
| `投影：` | 首点到**当前光标点**的水平距离（GCJ-02 用 `map.distance` 累加）；非绘制态显示已选线总长 | `—` |
| `高差：` | `points[i].z`（**本期新增可选字段**，由用户手填或地形模块回写）；无 `z` → `—` | `—` |
| `流速：` | `v = Q / (π·(D/2)²)`；`Q` 取 `plot.designFlow`（可选字段），`D` 取 `trunks[i].params.dn`；任一缺失 → `—` | `—` |
| `捕捉：` | 开关状态 | `开启` |

**要不要接地形 DEM**：本期不接。地形模块有自己的高程口径（`polyLatLng` + 局部米制投影），把它拉进地图页会引入一次跨模块强耦合，且 DEM 在离线/断网时不可用。**留接口不实现**：`points[i].z` 字段先支持，未来地形模块回写即可。

**流速按哪段算**：按**当前选中线**算，不按"最大段"。状态栏显示的是"这条线"的工程概览，不是校核结果；校核归水力页。

## 13. 五期 · 坐标反算 + 三类捕捉接通（v835）

> 就是上面 §12 结尾「仍未做」的第二条。这条**不是加功能，是先证明它不会做错** ——
> 阀门 / 支管起点 / 分区顶点在 `tlDiagramData` 里是**画布世界米坐标**，
> 反算成经纬度只要符号搞反，就是整块地南北颠倒。

### 13.1 先定性：这不是"可能有问题"，是"确实差 170 米"

`tlDiagramData` 是「真实地块坐标契约」（`world:'meter'`），顶点取自 `window.measuredPolygon`。
而同一个 `__runyeGeoBase` 下，站内存在**两套 y 方向**：

| 数据 | y 方向 | 出处 |
|---|---|---|
| `plot.poly`（地图页存库） | 北 = **+y** | `online-map.js:2315` `y:ys[i]`（未取反） |
| `measuredPolygon` / `tlDiagramData` | 北 = **−y** | `inline-16.js:143` `y:-ys[i]`（v217 垂直镜像） |
| `__runyeMapFramePoly` | 北 = **+y** | `inline-16.js:146` `y:ys[i]` |

而且地块库里的历史数据**两种都存在**（`inline-13.js:240` 的 `saveCurrent` 存的是已翻的
`measuredPolygon`，而地图页存的是未翻的）—— 连站点自己都要靠 `ryOrientPlotPoly()`
去判方向。

实测（`_probe_trunk_p5_geo.mjs`，300 m × 170 m 地块）：**选错符号，RMS 误差正好 170.0 m**，
等于地块南北向高度，反算点整片跑到地块外的空气里。

### 13.2 做法：不猜符号，用地块环当标尺自校准

```
polyLatLng（权威 GCJ-02） ×  dd.poly（世界米）
   ├─ 候选 A：lat = refLat + y/MLAT      （北 = +y）
   └─ 候选 B：lat = refLat − y/MLAT      （北 = −y）
       ↓ 各算一次 RMS（米）
   选 RMS 小的那个；要求 best < 0.5 m 且 other > 1 m
       ↓ 对不上 / 两个都像（地块近似东西向一条线）
   **拒绝反算** —— 这三类静默跳过。宁可少吸一个点，不要吸到错误位置。
```

### 13.5 接通后必须守住的一条：地块归属

`tlDiagramData` 属于「分区页当前地块」（`window.currentPlotId`）；
而捕捉服务的地块是「地图页正在编辑的那块」（`currentMapPlotId`，IIFE 私有）。
**两者不是同一块时，把前者的阀门吸到后者身上 = 吸到别人家的管子。**

`trunkGeoBridge()` 里一行守卫：

```js
if(String(window.currentPlotId||'')!==String(currentMapPlotId||'')) return null;
```

`_probe_trunk_p6_snap.mjs` H3 专门锁这条：把 `currentPlotId` 改成另一块后再调
`refreshSnapTargets()`，三类计数必须**整体归零**且 `snapExtras===null`；
H4 同时验「没误伤原有三类」—— 地块顶点 / 水源 / 干线拐点仍然在。

### 13.6 五期过程中必须记下来的三件事

1. **`#plotLibList` 在本版 `index.html` 里已经不存在了**（只剩一行注释说明
   `renderLib` 会对它判空）。地块库列表面板被剥离后，「设为当前」这个入口在页面上
   **不可达**。所以 p5 的第二个场景不是"走第二条 UI 路径"，而是**手工构造 +y 口径**
   来覆盖另一侧符号 —— 报告里如实写清楚，别让人以为测了两个入口。

2. **写回文件时别让工具改行尾。** `python` 的 `io.open(p,'w')` 在 Windows 上默认
   `newline=None`，会把 `\n` 统统转成 `\r\n`。而 `tests/plot_transfer.test.cjs:208`
   是靠**按换行切源码片段**定位 import handler 的（`'\n  };\n\n  renderMyPlots();'`），
   CRLF 下 `\r\n\r\n` 匹配不上 ⇒ 该测试直接 `ERR_ASSERTION`。
   四个文件（`online-map.js` / `index.html` / `sw.js` / `trunk-geo.js`）被整体转成 CRLF，
   是 `check.cjs` 报出来的。**修法**：`io.open(f,'wb').write(b.replace(b'\r\n',b'\n'))`，
   改完用 `b.count(b'\r\n')==0` 复核（`grep -c $'\r$'` 在 Git Bash 下不可靠，会误报）。

3. **分区网格交点要限量。** `RyTrunkSnap.nearest()` 每帧对**全部**候选做一次投影，
   大网格（20×20）会多出 441 个点，mousemove 直接掉帧。
   `ZONE_VERT_CAP = 150`，超了就不接分区顶点（阀门与支管起点照常），
   并在 `snapExtras.zoneNote` 里留 `capped:<n>` 痕迹。

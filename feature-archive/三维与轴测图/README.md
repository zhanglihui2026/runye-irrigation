# 三维预览与轴测图功能归档

本目录保存从主程序运行链路中完整摘除的三级轴测图、三维预览及其专属导航适配代码，供以后按需恢复。归档不代表功能已删除。

## 归档范围

- `source/`：轴测 SVG 渲染器、独立施工网络模型/编辑器、产品目录、Three.js 3D 预览、轴测统计与工具栏代码、轴测导航插件及专属样式。
- `integration-snapshot/`：本次剥离前的页面装配与运行接线快照，包括页面、Service Worker、插件清单、导航/DXF入口、图面状态存档和相关脚本。
- `manifest.json`：归档文件和源文件的 SHA-256 校验记录。

`integration-snapshot/index.html` 是恢复旧入口和视图标签的主要依据。`integration-snapshot/mod/style-01.css` 保存本次剥离后的当前样式快照；`source/mod/style-01.css` 是 Git 跟踪基线中的完整样式，包含轴测选择器，可用来恢复轴测皮肤。项目原有未提交界面改动不应被基线样式覆盖。

## 当前边界

- 主程序不再加载轴测视图、轴测统计/编辑器、Three.js 预览、3D 专属库或轴测导航入口。
- 在线地图、地块分区、二维三级工作区、管路绘制、材料清单和水力计算仍由主程序负责。
- `tlDiagramData` 与共享手工管段/节点数据仍是二维工作区和水力/材料流程使用的数据；旧项目中的 `isoDiagram.data` 只保留兼容读取，不会启动轴测功能。
- Three.js 原先按需加载，因此剥离可确定地减少离线核心缓存和可达运行代码；不把它描述为必然降低每次启动的内存占用。

## 恢复步骤

1. 对照本目录的 `integration-snapshot/` 与 `source/`，恢复所需文件和入口；不要把整份快照直接覆盖现有主程序。
2. 只恢复要启用的轴测入口、宿主动作、插件声明和样式；如果不需要3D预览，不要恢复 Three.js 资源及 `runye-pipe3d.js`。
3. 更新 `index.html` 的资源顺序、`plugins.json` 和 `sw.js` 的 `CORE` / `VERSION`，保证页面加载与离线缓存一致。
4. 核对共享数据兼容：二维图面数据仍以 `tlDiagramData` 为准，轴测/施工模型不得反向写入水力核心数据。
5. 使用仓库现有检查入口验证恢复后的页面、资源缓存、会员门控和图面数据边界。

归档来源、路径和摘要以 `manifest.json` 为准。不要将此目录作为页面运行资源或 Service Worker 预缓存资源。
